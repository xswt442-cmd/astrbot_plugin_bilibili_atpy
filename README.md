# atpy

用你自己的B站账号，每天在活跃时段随机跑几轮：搜一个怪视频，让模型写一句十字以内的锐评，@ 几个朋友发在评论区，同时把结果同步到 QQ 群。

## 它做一次什么

1. 从关键词池里抽一个词（离谱 / 抽象 / 整活 / 未解之谜……）
2. 搜视频，丢掉播放量太低（没人看）和太高（全网刷过）的
3. 把标题、UP主、分区、简介交给模型，要一句话点评
4. 拼成 `@张三 @李四 这不科学` 发到视频评论区
5. 在配置的 QQ 群说一声「刚刷到一个：……」
6. 记下 bvid，同一个视频不会发第二次

每天 3-5 轮，时间在活跃时段内随机分段，不会挤在一堆。

## 为什么不按「最新发布」搜

实测过 B站搜索的五个排序值（2026-10-21，匿名请求）：

| 排序 | 播放量 | 发布时间 |
|---|---|---|
| `pubdate` | 0 - 5 | 当天刚发的 |
| `click` | 1700 万起 | 194 天前之后 |
| `dm` / `scores` | 百万级 | 几百到几千天前 |
| `totalrank` | 263 - 584 万，跨度最大 | 0 - 1600 天 |

按 `pubdate` 拿到的全是刚上传、播放还是 0 的片子，一条都过不了门槛；
按 `click` 全是几年前的老爆款。只有 `totalrank` 能同时给出「播放量跨度大 + 有新的」。

## 配置

| 配置项 | 说明 |
|---|---|
| `sessdata` / `bili_jct` | B站登录态。浏览器登录后 F12 → Application → Cookies 复制 |
| `friends` | 朋友的B站昵称，逗号分隔。必须和对方当前昵称完全一致 |
| `notify_umo` | 发完往哪个会话说一声。在目标群发 `/atpy UMO` 取这一串 |
| `rounds_min` / `rounds_max` | 每天几轮，默认 3-5 |
| `active_start_hour` / `active_end_hour` | 活跃时段，默认 9-23 点 |
| `min_play` / `max_play` | 播放量区间，默认 10000-200000 |
| `max_days_old` | 只要多少天内发布的，默认 30 天 |
| `keywords` | 自定义搜索词，逗号分隔。填了就只用这些词 |
| `provider_id` | 写锐评用哪个模型，留空用第一个已加载的 |
| `dry_run` | 预览模式，只选片和写评，不发评论 |

第一次部署建议先开 `dry_run` 跑一天，看看选出来的片子和锐评对不对味，再关掉。

## 指令

```
/atpy 现在    立刻跑一轮（会真的发评论）
/atpy 预览    只生成不发
/atpy 最近    最近发过的五条
/atpy 状态    登录态、今日剩余档期
/atpy UMO     取当前会话标识
/atpy 帮助    列出全部指令
```

模型也能调 `recent_bili_critics` 查最近发过什么，聊天时可以被问起。

## 关于 @ 能不能生效

B站评论区的 @ 不需要额外参数，就是正文里写 `@昵称`，由服务端解析。所以：

- 昵称必须**一字不差**，写错了就只是纯文本，对方收不到通知
- 昵称里带空格时，解析可能断在空格处，先用小号试一次
- @ 的对象和你的账号没有互关关系时，能否真的送达没有保证

第一次跑请用小号，手动发一条验证。

## 风险

带 @ 的评论是B站判定「营销引流」的高危行为。一天 3-5 条已经是偏保守的上限。被风控的表现是评论发不出去并返回 `-403` 或 `12015`，插件会在日志里写明。

不要用主号。
